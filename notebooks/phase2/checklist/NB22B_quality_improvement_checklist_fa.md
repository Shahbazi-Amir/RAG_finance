## هدف و مرز

مصرف کارهای موجود، انجام فقط اصلاح یا اتصال لازم و ساخت تصمیم پذیرش برای نسخهٔ مشخص. NB22 برای checkpoint فعلی بسته شده است؛ این نوت‌بوک نتایج تاریخی را بازنویسی نمی‌کند و جای NB23 نیست. منطق اصلاح در مؤلفهٔ تولیدکنندهٔ مسئول حفظ و این نوت‌بوک مجری آزمایش و گزارش آن است. ساخت این فایل، پذیرش Release یا پایان فاز دو نیست.

## سیاست ارزیابی و داده

- Test تاریخی دیده شده؛ از آن برای انتخاب پارامتر/مدل استفاده نشود. آمار آن تشخیصی و تاریخی بماند.
- Holdout واقعاً دست‌نخورده پیش از ادعای نهایی بررسی شود؛ اگر کافی نبود طرح مجموعهٔ مستقل تازه، نسخه، دلیل و تأیید مرجع ثبت شود. Test دیده‌شده مستقل نام نگیرد.
- اصلاح احتمالی Gold/نگاشت فقط برای خطای اثبات‌شده با نسخه و Lineage؛ تغییر برای بالا رفتن امتیاز ممنوع است.
- رأی معنایی کافیِ هم‌نسخه دوباره ارسال نشود. نامعین و اختلاف از فقدان Artifact جدا باشند.
- Confidence توصیفی، احتمال حضور شاهد و احتمال صحت پاسخ یکی نیستند؛ کالیبراسیون قبلی به هدفی متفاوت تعمیم نیابد.

## قواعد مشترک اجرا

- هر اقدام با شماره، عنوان، شرط پایان، تعداد زیرکار و بستهٔ اجرایی معرفی شود؛ سپس Markdown فارسی RTL و یک سل کامل تجمیعی ارائه شود. شمارهٔ سل با اقدام یکی نیست.
- ابتدا گزارش نهایی، Manifest، Cache و کد تولیدکنندهٔ لازم مصرف شود؛ کار سالم و داوری موفق دوباره اجرا نشوند. نبود فایل در GitHub یا Parser ناموفق، نبود کار نیست.
- اقدام انجام‌شده با شاهد کافی در دامنهٔ واقعی بسته شود؛ مربع باز این برنامه، حکم انجام‌نشدن کار تاریخی نیست. Schema و Enum از قرارداد واقعی گرفته شوند.
- ثبت ادامه‌پذیر: `اقدام/زیرکار → Producer/Cell → مسیر/نسخه/تعریف Hash → جمعیت/واحد → تصمیم قبلی → کار تازه → Validation/Reload → محدودیت و بستهٔ بعد`.
- از دفتر شواهد موجود استفاده شود؛ برای هر مشاهدهٔ خواندنی گزارش و Manifest موازی ساخته نشود. بازخوانی فقط به علت تغییر مؤثر، تعارض یا نیاز مشخص مصرف‌کننده باشد.
- تعداد اقدام، سل، سؤال، تست و درخواست API جداست؛ درصد پیشرفت یا هزینهٔ حدسی ثبت نشود.
- API برای Hash، Join، Schema، شمارش و بسته‌بندی لازم نیست. ضرورت، تعداد پرونده و درخواست، Prompt، مدل، تعرفه، هزینه، توقف، Attempt و Resume قبل از اجرای تازه روشن شوند.
- در نیاز واقعی به API از کد موفق همان کار در NB21C استفاده شود؛ همزمانی ۱۸تایی سابقه است، نه مجوز یا مقدار پیش‌فرض. ارسال مجدد Attempt نامعلوم و Retry پنهان ممنوع است.
- Raw، Golden، Split، Rank/Score، پاسخ، رأی و Config تاریخی بدون نسخه و دامنهٔ مجاز تغییر نکنند. نسخهٔ مشتق Lineage داشته باشد؛ آستانه برای گرفتن PASS پایین نیاید.
- تعویق هلث‌چک/اجرای پاک نوت‌بوک‌های قبلی و اقدام ۴۸ NB21 برای مرحلهٔ بهینه‌سازی حفظ شود؛ خودکار باز نشود و PASS هم نام نگیرد.
- نوت‌بوک تازه مستقل از History کرنل قبلی باشد؛ C01 فقط Imports و C02 دریافت فقط‌خواندنی ورودی‌های صریح. مدل و دانلود خودکار در Bootstrap وارد نشود.
- ذخیرهٔ پایدار Atomic، رفتار برخورد با فایل متفاوت، Validation و Reload مستقل داشته باشد. اصل شاهد و خروجی ناموفق حفظ شوند.
- هر تیک فقط در دامنهٔ شرط پایان واقعی ثبت شود. پایان گزارش، PASS کیفیت، سلامت فنی و پذیرش Release یکسان نیستند.
- تهیهٔ این سند مجوز مدل، هزینه، Commit، Push، Deploy یا تغییر تیک مخزن نیست.

## معیارها، ترتیب و شرط پایان

- Recall@10≥۰٫۸۵، nDCG@10≥۰٫۷۵ و F1 نبود پاسخ≥۰٫۸۵ فقط در دامنه و مرجع معتبر قرارداد.
- صحت استناد، مکان استناد و پوشش factual حد مطلق ۰٫۹۵ دارند؛ baseline و عدم‌افت سازگار نیز بررسی شوند.
- نرخ factual بدون پشتوانه حداکثر ۰٫۰۳ و ادعای بحرانی بدون پشتوانه صفر؛ همهٔ قیود C057 مصرف شوند.
- ایمنی بحرانی صفر نقض، با پوشش موارد بحرانی درون دامنه؛ مجهول بحرانی مانع PASS است.
- سنجهٔ بدون حد مطلق با «عدد خوب به نظر می‌رسد» پذیرفته نمی‌شود؛ شرط قرارداد/عدم‌افت لازم است.
- این هدف‌های داخلی، تضمین یا حد رسمی عمومی دانش‌بنیان نیستند.

اقدامات ۱–۳ قبل از آزمایش، ۴–۶ چرخهٔ محدود، ۷–۱۰ کفایت معنایی، ۱۱ بعد از تعیین مرز اجرای مجاز، ۱۲ بعد از فریز، و ۱۳–۱۴ بستن نسخه‌اند. بخش مستقل ۷–۱۰ می‌تواند با بررسی بازیابی پیش برود، بدون جابه‌جایی نسخهٔ مبنا. همهٔ کارها لزوماً API یا بازاجرای کل جمعیت ندارند.

پس از پذیرش، نسخه به NB23 منتقل شود. پیش‌نویس قرارداد NB23 می‌تواند پیش‌تر آماده شود؛ جای شرط پذیرش را نمی‌گیرد.

## زمان و هزینه

زمان قطعی و تعداد درخواست از ۱۴ اقدام یا ۱۲ BLOCKED معلوم نمی‌شود. برآورد اولیهٔ برنامه‌ریزی: حدود ۲–۵ روز کاری برای چرخهٔ محدود اول بازیابی و حدود ۱–۳ هفته یا بیشتر برای مجموعهٔ پذیرش، با فرض دسترسی به کش، مرجع و مجری. تضمین رسیدن به هدف نیست و انتظار متخصص، آزمون مستقل و اجرای مدل می‌تواند آن را تغییر دهد؛ هلث‌چک موکول‌شده در این برآورد نیست. در اقدام ۴ بودجهٔ همان بسته دقیق شود؛ هزینه و تعداد API کل فعلاً نامشخص است.

## وضعیت اختتام

برای هر اقدام دامنهٔ تیک، شاهد، کنترل و شکاف ثبت شود. ۱۴ تیک دامنه‌دار به‌تنهایی پذیرش کل محصول نیست. اگر Gate پاس نشد، گزارش کاملِ عدم پذیرش معتبر است؛ پایان فاز دو یا ورودی پذیرفته‌شدهٔ NB23 اعلام نشود.
