## قواعد وضعیت و ثبت شاهد

تمام مربع‌های زیر بازند؛ تهیهٔ این برنامه، انجام اقدامات نیست. هر تیک فقط در دامنهٔ عنوان خودش و پس از خروجی واقعی ثبت می‌شود. ثبت یک مانع می‌تواند تکمیل کار مستندسازی باشد، ولی مانع را حل‌شده نمی‌کند. درصد پیشرفت تخمینی و تعداد درخواست مدلِ حدسی درج نمی‌شود.

هر ردیف دفتر اتصال حداقل شامل این‌ها باشد:

`requirement_id → producer/cell → artifact/version → hash و تعریف آن → scope/population → existing_decision → usable_scope → gap → owner → acceptance_evidence`

نتیجهٔ موجود و متصل، نیازمند Adapter، دسترسی‌نیافته، تعارض نسخه و شکاف واقعی از هم جدا باشند. Metadata یا نتیجهٔ مفقود ساخته نشود. نام Statusهای ماشینی نهایی از Schema واقعی گرفته شود؛ عنوان‌های توضیحی این برنامه Schema جدید محسوب نمی‌شوند.

## ترتیب و نقطهٔ شروع

ابتدا C01 فقط Imports/Bootstrap؛ سپس C02 پیش‌بررسی فقط‌خواندنی پنج فایل نهایی و وجود Notebook محلی. خروجی C02 برای ساخت Reader متناسب با Schema واقعی مصرف شود. تا آن زمان ادعای دریافت بسته، هویت نسخهٔ محلی یا PASS ورودی‌ها نداریم. فایل تعیین‌کنندهٔ موجود دوباره تولید نشود.

چهار بستهٔ اول می‌توانند بخش مستقل خود را پیش ببرند، اما شکست وابستگی اجازهٔ عبور مرحلهٔ وابسته را نمی‌دهد. دو FAIL بازیابی به NB16/NB17 و نسخهٔ مربوط وصل شوند؛ تغییر Threshold یا retuning با Test برای بستن NB22 مجاز نیست. چت ناظر فقط برای تعارض واقعی قرارداد/دامنه/پذیرش، با شاهد و اثر تصمیم درگیر شود.

## ادامهٔ NB23

پس از NB22، چک‌لیست جدا بر مبنای ده الزام نقشه ساخته می‌شود: Release پذیرفته‌شده، Request schema، Response schema، Citation object، statusها، Version trace، fixtures، backward compatibility، sample conversations و readiness gate.
