## وضعیت ورودی و مرز مسئولیت

NB22 با checkpoint فنی معتبر و Release پذیرفته‌نشده برای نسخهٔ فعلی بسته شده است. C054 تحویل‌نامه، C056 کنترل مستقل بازیابی و C058 کارهای بهبود را ثبت کرده‌اند. آخرین Gate محفوظ: دو FAIL، دوازده BLOCKED و دو PASS.

دو دامنه جدا:

- **پیش‌نویس:** طراحی Schema و تست مصنوعی یا مصرف نمونهٔ تاریخی ممکن است؛ ورودی candidate و خروجی draft نام بگیرد. mock پذیرش موتور نیست.
- **تحویل رسمی:** اقدام ۱ باید Release پذیرفته‌شده و شرایط مصرفش را احراز کند؛ سپس Gate نهایی اقدام ۱۰ قابل پذیرش رسمی است.

NB23 محل بهبود موتور، تغییر Gold/Threshold یا دورزدن Gate نیست. Backend، Auth، دیتابیس، UI، Deploy و پذیرش مصرف‌کننده در Module 00 فاز سه اینجا پیاده‌سازی نمی‌شوند. نوت‌بوک خالی و پیش‌نویس قرارداد، پایان فاز دو نیستند.

## قواعد مشترک اجرا

- هر اقدام با شماره، عنوان، شرط پایان، تعداد زیرکار و بستهٔ اجرایی معرفی شود؛ سپس Markdown فارسی RTL و یک سل کامل تجمیعی ارائه شود. شمارهٔ سل با اقدام یکی نیست.
- ابتدا گزارش نهایی، Manifest، Cache و کد تولیدکنندهٔ لازم مصرف شود؛ کار سالم و داوری موفق دوباره اجرا نشوند. نبود فایل در GitHub یا Parser ناموفق، نبود کار نیست.
- اقدام انجام‌شده با شاهد کافی در دامنهٔ واقعی بسته شود؛ مربع باز این برنامه، حکم انجام‌نشدن کار تاریخی نیست. Schema و Enum از قرارداد واقعی گرفته شوند.
- ثبت ادامه‌پذیر: `اقدام/زیرکار → Producer/Cell → مسیر/نسخه/تعریف Hash → جمعیت/واحد → تصمیم قبلی → کار تازه → Validation/Reload → محدودیت و بستهٔ بعد`.
- از دفتر شواهد موجود استفاده شود؛ برای هر مشاهدهٔ خواندنی گزارش و Manifest موازی ساخته نشود. بازخوانی فقط به علت تغییر مؤثر، تعارض یا نیاز مشخص مصرف‌کننده باشد.
- تعداد اقدام، سل، سؤال، تست و درخواست API جداست؛ درصد پیشرفت یا هزینهٔ حدسی ثبت نشود.
- API برای Hash، Join، Schema، شمارش و بسته‌بندی لازم نیست. ضرورت، تعداد پرونده و درخواست، Prompt، مدل، تعرفه، هزینه، توقف، Attempt و Resume قبل از اجرای تازه روشن شوند.
- در نیاز واقعی به API از کد موفق همان کار در NB21C استفاده شود؛ همزمانی ۱۸تایی سابقه است، نه مجوز یا مقدار پیش‌فرض. ارسال مجدد Attempt نامعلوم و Retry پنهان ممنوع است.
- Raw، Golden، Split، Rank/Score، پاسخ، رأی و Config تاریخی بدون نسخه و دامنهٔ مجاز تغییر نکنند. نسخهٔ مشتق Lineage داشته باشد؛ آستانه برای گرفتن PASS پایین نیاید.
- تعویق هلث‌چک/اجرای پاک نوت‌بوک‌های قبلی و اقدام ۴۸ NB21 برای مرحلهٔ بهینه‌سازی حفظ شود؛ خودکار باز نشود و PASS هم نام نگیرد.
- نوت‌بوک تازه مستقل از History کرنل قبلی باشد؛ C01 فقط Imports و C02 دریافت فقط‌خواندنی ورودی‌های صریح. مدل و دانلود خودکار در Bootstrap وارد نشود.
- ذخیرهٔ پایدار Atomic، رفتار برخورد با فایل متفاوت، Validation و Reload مستقل داشته باشد. اصل شاهد و خروجی ناموفق حفظ شوند.
- هر تیک فقط در دامنهٔ شرط پایان واقعی ثبت شود. پایان گزارش، PASS کیفیت، سلامت فنی و پذیرش Release یکسان نیستند.
- تهیهٔ این سند مجوز مدل، هزینه، Commit، Push، Deploy یا تغییر تیک مخزن نیست.
