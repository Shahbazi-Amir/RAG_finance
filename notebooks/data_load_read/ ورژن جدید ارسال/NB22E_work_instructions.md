# دستورالعمل اجرای نوت‌بوک NB22E

## قالب پاسخ
- توضیحات کوتاه و مستقیم باشند، مگر توضیح کامل درخواست شود.
- هر گام اجرایی شامل توضیح کوتاه، سل Markdown و سپس سل کد تجمیعی باشد.
- کارهای مرتبط تا جای ممکن در یک سل جمع شوند.
- خروجی اجرای کاربر بررسی شود و کار ادامه پیدا کند.
- برای تصمیم‌های معمول اجرایی تأیید مکرر درخواست نشود؛ کاربر تصمیم‌های مدنظرش را اعلام می‌کند.

## قالب سل Markdown
- متن فارسی راست‌چین باشد و داخل قالب زیر قرار بگیرد:

```markdown
<div dir="rtl" align="right">

### NB22E-CXXX — عنوان گام

توضیح کوتاه هدف، عملیات و محدودیت‌های واقعی گام.

</div>
```

## قالب سل کد
- دو خط اول هر سل: شماره و عنوان کوتاه در خط اول؛ توضیح عملکرد در خط دوم.

```python
# NB22E-C069 — Review candidate evidence relevance.
# Record evidence-based proposals while preserving historical Gold.
```

- شماره‌گذاری مطابق سل‌های موجود ادامه پیدا کند.
- هنگام اصلاح همان سل، شماره آن حفظ شود.
- در صورت خطا، سل کامل اصلاح‌شده ارائه شود، نه صرفاً تکه‌ای از اصلاح.

## مدیریت importها
- تمام importها فقط در NB22E-C001 قرار بگیرند.
- در سل‌های بعدی هیچ import تکراری، حتی داخل تابع، اضافه نشود.
- اگر وابستگی تازه لازم شد، تغییر لازم برای C001 ارائه شود.
- نصب یا دانلود وابستگی بخشی از سل import نباشد.
- نبود وابستگی ضروری پیش از شروع عملیات گزارش شود.

## ادامه کار
- از سل‌های ریز و گزارش‌های تکراری بدون پیشرفت عملی خودداری شود.
- فقط اطلاعات همین چت و فایل‌های ارائه‌شده همین پروژه استفاده شوند.
- ساختار فایل یا نتیجه خوانده‌نشده حدس زده نشود؛ عدم اطمینان صریح بیان شود.
- پیشنهاد داوری، مرجع تأییدشده و پذیرش نهایی جدا نگه داشته شوند.
- اصلاح مرجع ارزیابی، بهبود مدل گزارش نشود.
- Gold تاریخی، کش و خروجی‌های ذخیره‌شده حفظ شوند.
- Run All برای ادامه این مراحل درخواست نشود.
- اجرای مدل، API یا دانلود تازه بدون نیاز واقعی به کار اضافه نشود.

## تحویل فایل
- وقتی فایل .md درخواست می‌شود، فایل واقعی قابل دانلود ارائه شود؛ نمایش متن در بلوک کد به‌تنهایی کافی نیست.
